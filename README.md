# bibilili

一个**个人自用**的 Android 客户端，用来看哔哩哔哩上的**影视 / 电视剧 / 纪录片 / 综艺 / 番剧**等正片内容（PGC），不含 UP 主投稿视频。

> 当前阶段：**设计与可行性论证**，尚未开始编码。

## ✅ 可行性速览

| 需求 | 结论 |
|---|---|
| 首页历史过滤掉 UP 主视频 | ✅ **能，纯客户端，不需要自建服务器**（按 `history.business == "pgc"` 过滤 + Room 本地镜像） |
| 首页收藏 | ✅ 能（追番/追剧列表天然分好类） |
| 影视 / 番剧频道页（四标签 + 金刚位） | ✅ 能（PGC 频道页接口 + 索引筛选兜底） |
| 播放（DASH / 多清晰度 / 多季选集 / 全套手势） | ✅ 能（Media3 ExoPlayer，需注入 Referer） |
| 详情页（原名/别名/演职人员/制作信息） | ⚠️ 能，最全的数据在 App 端接口，需实测 |
| 豆瓣评分 | ⚠️ **能但不稳定**，建议二期做成可插拔模块 |
| 投屏 | ⚠️ **能但要降级**，一期最高 1080P |

详见 [`docs/02`](docs/02-接口可行性验证.md)。

## ⚠️ 一个必须说明的前提

这批文档写于 **Claude Code 云端沙箱**，该环境**无法访问 `api.bilibili.com`**（出网只放行软件包镜像源），
所以文中的接口来自公开逆向资料与既有知识，**不是实测结果**。

文档里每条接口都标了置信度（✅ / ⚠️ / ❓），
**开工第一步是 [`docs/03` §8 的 M0「接口探针」](docs/03-架构与实现方案.md)：把所有标 ⚠️/❓ 的接口先用 curl 打一遍再写代码。**

## 🔒 使用边界

本项目仅供**个人自用**：使用自己的账号、只访问账号本就有权访问的内容、不上架商店、不公开分发、不绕过任何付费校验、不做商业化。
详见 [`docs/04` §2](docs/04-风险与待决问题.md)。
