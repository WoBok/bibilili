## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | **Kotlin 2.x**（K2） | Android 一等公民 |
| UI | **Jetpack Compose + Material 3 Expressive** | 需求 X-3 要「良好的交互动画」，Compose 的 `AnimatedContent` / `SharedTransitionLayout` / `Modifier.animate*` 做转场远比 View 体系省力 |
| 导航 | **Navigation-Compose（type-safe routes）** + `SharedTransitionLayout` | 海报 → 播放页的共享元素转场是本 App 的招牌动效 |
| 架构 | **MVVM + UDF**（单向数据流：`UiState` / `UiEvent` / `UiAction`） | 播放器状态复杂，UDF 能显著降低状态同步 bug |
| DI | **Hilt** | 生态最成熟 |
| 网络 | **Retrofit + OkHttp + kotlinx.serialization** | 签名逻辑做成 Interceptor，业务层零感知 |
| 图片 | **Coil 3** | Compose 原生、支持自定义 Header（B 站图床也要 Referer） |
| 本地存储 | **Room**（历史镜像/详情缓存/片头片尾标记）+ **DataStore**（偏好） | 见 02 §3.1 |
| 凭证存储 | **DataStore + Tink / EncryptedSharedPreferences** | Cookie/token 是敏感数据，不能明文落盘 |
| 分页 | **Paging 3** | 索引页/筛选页数据量大 |
| 播放器 | **Media3（ExoPlayer + MediaSession + UI）** | DASH 原生支持、PiP、后台播放、通知栏控制 |
| 投屏 | **jUPnP**（Cling 活跃分支） | Cling 已停更 |
| 异步 | **Coroutines + Flow** | — |
| 最低版本 | **minSdk 26 / targetSdk 35** | 自用，不必兼容太老；26 才有较好的通知与前台服务模型 |

## 2. 模块划分（Gradle 多模块）

```

:core:player             播放器封装：PlayerHolder、DASH→MPD 构建器、手势状态机、SleepTimer、SkipController
:core:cast               DLNA 设备发现与 AVTransport 控制 + Referer 转发代理
:feature:login           扫码登录（Web + TV 双轨）
:feature:home            首页（历史 / 收藏）+ 左滑用户页
```

## 3. 数据分层

```
UI (Compose)
  ↕  UiState / UiAction
ViewModel
  ↕  suspend fun / Flow<Result<T>>
Repository          ← 唯一决定「读缓存还是读网络」的地方
  ├── RemoteDataSource (Retrofit)
  └── LocalDataSource  (Room / DataStore)
```

**统一结果类型**：
```kotlin
sealed interface ApiResult<out T> {
    data class Success<T>(val data: T) : ApiResult<T>
    data class Failure(val error: BiliError) : ApiResult<Nothing>
}

sealed class BiliError(val message: String) {
    data object NotLoggedIn          : BiliError("登录已失效，请重新扫码")      // -101
    data object RiskControl          : BiliError("请求被风控，请稍后再试")      // -352 / -412
    data object GeoRestricted        : BiliError("该内容在当前地区不可观看")    // -10403
    data object VipRequired          : BiliError("该清晰度需要大会员")
    data class  Network(val t: Throwable) : BiliError("网络异常")
    data class  Unknown(val code: Int, val msg: String) : BiliError(msg)
}
```
> **原则：任何一个错误都要有一句「人话」提示**，不允许出现裸露的 `-352`。

## 4. 网络层：签名与 Header

OkHttp 拦截器链（顺序很重要）：

```
CurlLogInterceptor (debug)
  → HeaderInterceptor      注入 UA / Referer / Origin
  → BuvidInterceptor       注入 buvid3 / buvid4（首次启动时 spi + ExClimbWuzhi 激活）
  → CookieInterceptor      注入 SESSDATA / bili_jct / DedeUserID
  → WbiSignInterceptor     对标记了 @Wbi 的接口追加 wts / w_rid
  → AppSignInterceptor     对标记了 @AppSign 的接口追加 appkey / ts / sign
  → RetryInterceptor       -412/-352 指数退避重试；主 CDN 失败切 backupUrl
```

**WBI 实现要点**：
```kotlin
// 1. img_key/sub_key 来自 nav 响应，按天缓存
// 2. rawKey = imgKey + subKey (64 chars)
// 3. mixinKey = MIXIN_KEY_ENC_TAB.map { rawKey[it] }.joinToString("").take(32)
// 4. query = params.toSortedMap().filterValue { 去掉 !'()* }.toQueryString() + "&wts=$ts"
// 5. w_rid = md5(query + mixinKey)
```
`MIXIN_KEY_ENC_TAB` 是一张固定的 64 元素重排表，**M0 阶段先用 curl 验证签名正确性再写进代码**。

**接口标注方式**（让签名对业务透明）：
```kotlin
@Wbi @GET("x/space/wbi/acc/info")
suspend fun getUserInfo(@Query("mid") mid: Long): BiliResp<AccInfo>
```

## 5. 播放器设计（本项目技术难点 Top 1）

### 5.1 取流 → 播放

```
PlayUrlRepository.fetch(epId, cid, qn)
  → PlayUrlResponse(dash)
  → DashManifestBuilder.build(dash, preferredQn, preferredCodec)   // JSON → MPD (内存)
  → DashMediaSource.Factory(BiliDataSourceFactory)                  // 注入 Referer/UA
  → ExoPlayer.setMediaSource(...)
```

`BiliDataSourceFactory` = `DefaultHttpDataSource.Factory()
  .setDefaultRequestProperties(mapOf("Referer" to "https://www.bilibili.com", "User-Agent" to UA))
  .setAllowCrossProtocolRedirects(true)`

**编码优先级**：AVC(7) > HEVC(12) > AV1(13)。
虽然 AV1 省流量，但**中低端安卓设备普遍没有 AV1 硬解**，软解会发烫掉帧。
→ 设置里给一个「优先编码」选项，默认 **AVC**，高端机可选 HEVC。

### 5.2 播放器状态机（PlayerUiState）

```kotlin
data class PlayerUiState(
    val season: SeasonDetail? = null,
    val currentEp: Episode? = null,
    val seasons: List<SeasonBrief> = emptyList(),   // P-6 多季
    val isFullscreen: Boolean = false,
    val controlsVisible: Boolean = true,            // F-1
    val speed: Float = 1.0f,
    val isLongPressBoosting: Boolean = false,       // F-6 长按倍速中
    val quality: Quality? = null,
    val availableQualities: List<Quality> = emptyList(), // 来自 support_formats
    val openSheet: PlayerSheet? = null,             // F-8: Episodes / Speed / Quality / Menu
    val sleepTimer: SleepTimerState = SleepTimerState.Off,
    val skipMark: SkipMark? = null,                 // F-4 跳过头尾
    val castState: CastState = CastState.Idle,
)
```

### 5.3 手势状态机

用 `awaitEachGesture` 手写，避免 `detectTapGestures` 的长按/双击互抢：

```
DOWN
 ├─ 200ms 内 UP，且 300ms 内有第二次 DOWN+UP → DOUBLE_TAP（左/右 → seek ∓ step；连击累加）
 ├─ 200ms 内 UP，无第二次                     → SINGLE_TAP（toggle 控制层）
 ├─ 按住 > 300ms 且未移动                      → LONG_PRESS（speed = boostSpeed，UP 时还原）
 └─ 移动超过 touchSlop                         → DRAG（水平=进度，左半垂直=亮度，右半垂直=音量）
```

**连击累加**：双击快进要做一个 800ms 的「连击窗口」，窗口内继续双击则累加秒数并只显示一个浮层（`-10s → -20s → -30s`），窗口结束才真正 `seekTo`。这是体验上和官方端拉开差距的细节。

### 5.4 各项开关的实现

| 功能 | 实现 |
|---|---|
| 定时关闭 | ViewModel 里一个 `CountDownFlow`；到点 `player.pause()` + 弹「已定时关闭」。额外提供「播完本集」——监听 `STATE_ENDED` |
| 跳过头尾 | 每 500ms 采样 `currentPosition`，进入 `[prologue.start, prologue.end]` 时 `seekTo(end)` 并 Toast「已跳过片头」。片尾同理，若开了自动连播则直接切下一集 |
| 自动连播 | `Player.Listener.onPlaybackStateChanged(STATE_ENDED)` → `playNext()`；当前季播完则查 `seasons[]` 跳下一季首集 |
| 快进步长 / 长按倍速 | DataStore 全局 Flow，竖屏与全屏共享（满足 F-5） |
| 进度记忆 | 退出/切集时写 Room + `POST x/v2/history/report` 双写 |
| 清晰度记忆 | 按「网络类型」分别记忆（WiFi 用 1080P+，蜂窝用 720P），避免流量爆炸 |

### 5.5 竖屏 ↔ 全屏切换

**不销毁 Player 实例**。用同一个 `ExoPlayer` 对象，只切换 `PlayerView` 的宿主容器：
- 方案：把播放器放在 `Activity` 级的 `Box` 中，用 `Modifier.animateBounds` / `LookaheadScope` 做位置与尺寸的过渡动画；
- 全屏时 `requestedOrientation = SENSOR_LANDSCAPE` + `WindowInsetsController.hide(systemBars)`；
- `AndroidView` 承载 `PlayerView` 时用 `remember` 保证不重建 SurfaceView（重建会黑一下）。

**同时支持画中画（PiP）**：`setPictureInPictureParams` + `onUserLeaveHint`，自用 App 体验加分项。

## 6. 首页历史同步（对应 02 §3.1 的方案 1+2）

```kotlin
suspend fun syncPgcHistory(force: Boolean) {
    val localNewest = dao.newestViewAt()
    var cursor = Cursor.INITIAL
    var pages = 0
    var collected = 0
    while (pages < MAX_PAGES && collected < TARGET_COUNT) {
        val page = remote.historyCursor(cursor)
        val pgc = page.list.filter { it.history.business == "pgc" }
        dao.upsertAll(pgc.map { it.toEntity() })
        collected += pgc.size
        if (!force && page.list.any { it.viewAt <= localNewest }) break  // 增量：追上本地即停
        cursor = page.cursor
        pages++
        delay(300)   // 频控，避免 -412
    }
}
```
- 冷启动：`MAX_PAGES = 10`、`TARGET_COUNT = 20`；
- 下拉刷新：增量模式（`force = false`），通常 1 页就追平；
- 首页 UI **始终读 Room 的 Flow**，同步是后台行为 → 秒开、永不空白。

## 7. 动效清单（对应 X-2 / X-3）

| 场景 | 动效 | 实现 |
|---|---|---|
| 海报 → 播放页 | **共享元素转场**：海报放大到播放器位置，标题淡入 | `SharedTransitionLayout` + `sharedElement()` |
| 首页 ↔ 用户页（U-1 左右滑） | 视差滑动：首页向右位移 + 缩放 0.92 + 圆角变大，用户页从左滑入 | `AnchoredDraggable` + `graphicsLayer` |
| 详情覆盖层（D-1） | 从播放器下沿向上滑入 + 背景模糊，播放器不动 | `AnimatedVisibility(slideInVertically + fadeIn)` |
| 全屏侧拉菜单（F-8） | 右侧抽屉滑入，列表项**依次错峰**淡入（stagger 30ms） | `AnimatedVisibility` + `animateItem` |
| 控制层显示/隐藏（F-1） | 上下渐变遮罩 + 控件淡入淡出 220ms | `AnimatedVisibility(fadeIn/fadeOut)` |
| 长按倍速（F-6） | 屏幕上方弹出「2.0× 快进中 ⏩」胶囊，带轻微弹性 | `spring(dampingRatio = MediumBouncy)` |
| 双击快进 | 左右半屏的**半圆水波纹**扩散 + 「-10 秒」数字跳动 | 自绘 `Canvas` + `Animatable` |
| 卡片加载 | **Shimmer 骨架屏**，不用 loading 圈 | `Modifier.placeholder` |
| 清晰度/倍速切换 | 选中项品牌色滑块位移（不是直接换色） | `animateDpAsState` |
| 底部 Tab 切换 | 图标微弹 + 指示条位移 | `spring` |

**动效统一 token**（放 `:core:designsystem`）：
```
Duration:  fast 120ms / normal 220ms / slow 400ms
Easing:    standard = CubicBezier(0.2, 0, 0, 1)   emphasized = CubicBezier(0.05, 0.7, 0.1, 1)
Spring:    bouncy = spring(0.6, 380)   smooth = spring(1f, 700)
```
> **纪律：所有动效必须响应系统「减少动态效果」设置**（`Settings.Global.ANIMATOR_DURATION_SCALE == 0` 时退化为瞬时）。

## 9. 工程约定

- **JSON 解析**：`Json { ignoreUnknownKeys = true; coerceInputValues = true }`，所有字段默认可空并给默认值。
- **模块级容错**：频道页的每个模块独立 try/catch，解析失败就跳过该模块，**绝不整页失败**。
- **接口常量集中管理**：所有 path / appkey / season_type 放 `:core:network` 的 `BiliApi.kt`，B 站改版时只改一处。
- **日志**：debug 构建打 curl 格式日志，方便直接复制到终端复现；release 关闭。
- **不写死档位**：清晰度列表来自 `support_formats`，倍速列表来自 F-7 常量，两者都不在 UI 层硬编码。
- **凭证绝不入日志、绝不进 git**。
